# YouTube 북마클릿 코어 기준

이 문서는 **공개 GitHub에 실제 YouTube 전용 추출 코드를 저장하지 않고**, 북마클릿 내부 코어의 역할과 입출력만 고정하기 위한 기준입니다.

실제 YouTube 전용 식별/추출/스트림 판별 코드는 북마크 URL 안에 유지합니다.

## 1. 코어 역할

북마클릿 코어는 다음만 담당합니다.

1. 현재 페이지가 일반 영상인지 Shorts인지 식별
2. 현재 영상 ID 확인
3. 현재 영상의 기본 메타데이터 확인
4. 접근 가능한 영상 스트림 조사
5. 접근 가능한 음성 스트림 조사
6. 실제 가능한 화질/음질 목록 생성
7. 사용자가 선택한 영상/음성 스트림 확정
8. 로컬 저장 시 실제 미디어 fetch 및 파일 저장 실행
9. 데이터 선택 시 YouTube 전용 최소 추출 실행
10. 공개 UI와 메시지 송수신

## 2. 현재 보존해야 할 검증 경로

아래 동작은 이미 Android 모바일 Whale에서 성공한 기준이므로 이후 리팩터링에서도 우선 보존합니다.

- 일반 영상 식별 및 저장
- Shorts 식별 및 저장
- 영상: 영상+음성이 함께 포함된 MP4 저장
- 음성: 음성 전용 파일 저장
- 실제 접근 가능한 형식만 후보로 사용
- 영상의 현재 검증 화질: 360p
- 저장 시 브라우저 파일 저장 선택 흐름 사용

고화질 영상/음성 분리 스트림 병합은 현재 코어 기본 범위에 넣지 않습니다.

## 3. 코어 내부 상태

UI에는 실제 스트림 주소를 상시 전달하지 않습니다.

코어 내부에서는 실행 중에만 다음 상태를 유지합니다.

- 현재 영상 ID
- 현재 영상 메타데이터
- 영상 후보 목록
- 음성 후보 목록
- UI 선택값과 실제 스트림 후보의 대응표
- 현재 실행 token

페이지를 새로고침하거나 실행을 종료하면 다시 조사합니다.

## 4. UI에 전달할 정보

초기화 시 공개 UI에는 다음만 전달합니다.

### 영상 정보

- 썸네일
- 제목
- 채널명
- 업로드일
- 길이
- 조회수

### 미디어 선택지

- 영상: 사용자 표시용 화질명 + 코어 내부 후보를 가리키는 임시 ID
- 음성: 사용자 표시용 음질명 + 코어 내부 후보를 가리키는 임시 ID

UI는 임시 ID의 의미나 실제 스트림 URL을 알 필요가 없습니다.

## 5. 영상 후보 규칙

- 사용자가 바로 재생 가능한 영상+음성 통합 스트림을 우선 사용
- 실제 URL이 존재하는 후보만 사용
- 접근 가능한 후보만 UI에 표시
- 같은 화질 후보가 여러 개면 코어가 가장 적합한 하나를 대표 후보로 정함
- 현재 성공 경로를 최우선으로 보존

## 6. 음성 후보 규칙

- 음성 전용 스트림만 후보로 사용
- 실제 접근 가능한 후보만 사용
- 가능한 후보를 음질 기준으로 정렬
- UI에는 파일 확장자보다 `음질` 중심으로 표시

## 7. 로컬 저장

사용자가 `로컬`을 선택하면 실제 파일 저장은 YouTube 페이지 안의 코어에서 실행합니다.

### 영상

- 선택된 영상 후보를 fetch
- Android 브라우저의 파일 저장 선택 흐름 사용
- MP4 파일명 생성

### 음성

- 선택된 음성 후보를 fetch
- Android 브라우저의 파일 저장 선택 흐름 사용
- 음성 파일명 생성

파일명은 영상 제목을 기본으로 하고 파일명에 사용할 수 없는 문자는 정리합니다.

## 8. Drive 저장

Drive 동작도 UI가 실제 YouTube 추출 규칙을 알지 않도록 합니다.

Drive 저장에 미디어 주소가 필요한 경우에도 코어가 **저장 실행 시점에만** 선택된 주소를 일시적으로 전달합니다.

주소를 GitHub 코드, localStorage, IndexedDB 또는 문서에 저장하지 않습니다.

## 9. 데이터 수집

데이터 코어는 `UI_SPEC.md`에서 사용자가 선택한 필드만 조사합니다.

1차 기본 필드:

- 썸네일
- 제목
- 영상 URL
- 채널명
- 업로드일
- 영상 길이
- 조회수
- 설명
- 태그
- 대본
- 댓글
- 좋아요
- 자막 원본
- 영상 ID
- 채널 ID
- 원본 메타데이터

댓글/대본처럼 추가 요청이 필요한 항목은 선택되지 않았으면 호출하지 않습니다.

## 10. 오류 원칙

한 기능의 실패가 다른 기능을 깨뜨리지 않도록 분리합니다.

예:

- 데이터 실패 + 영상 성공 → 영상 저장 가능
- 음성 후보 없음 + 영상 후보 있음 → 영상만 선택 가능
- Drive 실패 → 로컬 저장 경로는 유지

UI에는 사용자가 처리할 수 있는 짧은 상태 문구만 전달합니다.

## 11. 공개 저장소 금지 항목

다음은 이 문서에도 실제 값이나 구현 코드로 넣지 않습니다.

- YouTube 전용 핵심 추출 코드 전문
- 실행 중 얻은 미디어 URL
- 로그인/세션 정보
- 인증 쿠키
- OAuth 토큰
- 개인 계정 비밀값

## 12. 단계 3 완료 기준

다음 인터페이스가 고정되면 코어 정리 완료로 봅니다.

- 일반 영상/Shorts 공통 진입
- 영상 후보 목록
- 음성 후보 목록
- UI용 임시 선택 ID
- 통합 초기화 메시지
- 통합 저장 요청 메시지
- 상태 메시지

세부 메시지 형식은 `PROTOCOL.md`를 따릅니다.
