# YouTube 로컬 저장 연결 흐름

이 문서는 통합 UI의 `영상 / 음성` 선택을 현재 검증된 Android 모바일 로컬 저장 경로에 연결하는 기준입니다.

YouTube 전용 스트림 추출 코드 자체는 공개 저장소에 두지 않습니다.

## 1. 초기화

북마클릿 코어가 현재 영상/Shorts를 조사한 뒤 UI에 다음만 전달합니다.

- 영상 정보
- 실제 사용 가능한 영상 화질 목록
- 실제 사용 가능한 음성 음질 목록
- 각 후보를 가리키는 임시 ID

실제 미디어 URL은 UI 초기화 메시지에 포함하지 않습니다.

## 2. UI 선택

사용자는 다음을 선택합니다.

- `영상`
- `음성`
- 둘 다

영상 선택 시 화질을 고릅니다.

음성 선택 시 음질을 고릅니다.

저장 위치가 `로컬`이면 `ui.html`은 `YT_TOOL_ACTION / save-local` 메시지를 보냅니다.

## 3. 코어 후보 해석

코어는 UI가 돌려준 임시 ID를 실행 중 후보표에서 찾습니다.

- `video.id` → 영상+음성 통합 MP4 후보
- `audio.id` → 음성 전용 후보

후보표와 실제 URL은 현재 북마클릿 실행 동안에만 메모리에 유지합니다.

## 4. 현재 검증된 영상 저장 경로

1. 파일명: 현재 영상 제목 기반 `.mp4`
2. 파일명 금지 문자 정리
3. `showSaveFilePicker()` 호출
4. 미디어 URL `fetch`
5. 필요 시 `Range: bytes=0-` 사용
6. `response.body.pipeTo(await handle.createWritable())`
7. 성공/실패 상태를 UI에 반환

현재 Android 모바일 Whale에서 일반 영상과 Shorts 모두 이 계열의 저장 경로가 성공했습니다.

현재 검증된 통합 영상 화질은 360p입니다.

## 5. 현재 검증된 음성 저장 경로

1. 파일명: 현재 영상 제목 기반 음성 확장자
2. 파일명 금지 문자 정리
3. `showSaveFilePicker()` 호출
4. 선택된 음성 전용 URL `fetch`
5. 응답 스트림을 선택 파일에 기록
6. 성공/실패 상태를 UI에 반환

현재 검증 경로는 `audio/mp4` 계열 음성 파일 저장입니다.

## 6. 복수 선택

영상과 음성을 함께 선택할 수 있습니다.

다만 파일 선택창은 각 실제 파일마다 필요하므로 코어는 항목을 독립 작업으로 취급합니다.

한 항목의 실패가 다른 항목의 성공을 취소하지 않습니다.

## 7. 상태 메시지

예:

```text
영상 저장 준비 중…
영상 저장 완료
음성 저장 준비 중…
음성 저장 완료
```

오류 시에는 항목을 명시합니다.

```text
영상 저장 실패
음성 저장 취소됨
```

## 8. 공개/비공개 경계

공개 가능:

- UI
- 임시 ID 규격
- 일반 파일 저장 흐름
- 상태 처리

공개하지 않음:

- YouTube player 호출의 실제 핵심 구현 전문
- 스트림 판별 핵심 코드 전문
- 실행 중 실제 미디어 URL
- 계정/세션 정보

## 9. 단계 4 완료 기준

- `ui.html`이 `YT_TOOL_*` 통합 프로토콜 사용
- `로컬` 선택 시 `save-local` 요청 생성
- 영상 화질 임시 ID 전달
- 음성 음질 임시 ID 전달
- 코어가 임시 ID를 실제 후보로 해석하는 구조 고정
- 기존 Android 저장 성공 흐름 보존
- 항목별 성공/실패 상태 규격 고정
