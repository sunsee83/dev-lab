# Bookmarklets

이 폴더 아래 모든 북마클릿에 공통으로 적용하는 코드 배치 및 보안 원칙입니다.

## 북마크 URL 안

길이 제한을 고려해, 각 서비스에 종속적이고 중요도가 높은 짧은 로직을 우선 배치합니다.

- 서비스 전용 핵심 판별 로직
- 콘텐츠 식별 규칙
- 중요한 짧은 추출 로직
- 외부 본체와 연결하는 코드

예: Instagram 북마클릿이라면 현재 Reel/게시물 식별, 핵심 미디어·콘텐츠 판별 규칙처럼 서비스 구조에 직접 의존하는 짧은 로직을 둘 수 있습니다.

## GitHub 공개 코드

크기가 크거나 일반화 가능한 기능은 공개 본체 코드로 분리합니다.

- UI
- 파일 저장
- IndexedDB
- 썸네일 생성
- CSV/JSON 출력
- 일반적인 유틸리티

## 절대 금지: 비밀정보 저장

API 키, 비밀번호, 로그인 토큰 같은 진짜 비밀값은 절대 코드에 넣지 않습니다.

다음 정보는 GitHub에도 넣지 않고, 북마크 URL 안에도 넣지 않습니다.

- API 키
- 비밀번호
- 로그인 토큰 / 액세스 토큰 / 리프레시 토큰
- 세션 토큰
- 인증 쿠키 및 세션 값
- 계정 접근에 사용되는 기타 비밀값

이 원칙은 공개/비공개 저장소 여부와 관계없이 적용합니다. 예외 없이 지킵니다.

## 구조 문서 원칙

각 서비스 폴더에는 `PRODUCT_STRUCTURE.md` 같은 제품 구조 문서를 둡니다.

- 핵심 구조와 역할을 빠뜨리지 않고 짧게 정리합니다.
- 확정값과 가이드라인, 향후 기능을 구분합니다.
- 더 나은 구조가 생기면 코드보다 문서를 먼저 갱신합니다.

### UI 구조 정리 전용 형식

아래 형식은 **UI 구조를 정리하는 부분에만 적용**합니다. 데이터 흐름, 보안, 구현, 테스트 등 다른 문서 형식에는 강제하지 않습니다.

- 계단식 트리 구조
- 설명 없이 화면에 표시될 한글명 사용
- 위치는 `하단`, `좌측 위`, `우측 아래`처럼 표시
- 핵심 UI는 빠뜨리지 않고 중복·장문은 줄임

참고 프롬프트:

`UI 구조를 계단식 구조화로 작성해. 설명 없이 화면에 표시될 한글명으로 쓰고, 화면 위치는 하단·좌측 위처럼 표시해. 핵심은 빠뜨리지 말고 짧게 정리해.`

## 폴더 구조 원칙

서비스별 북마클릿은 하위 폴더로 구분합니다.

- `bookmarklets/instagram/`
- `bookmarklets/youtube/`
- `bookmarklets/x/`
- 기타 서비스별 폴더

한 북마클릿의 기능 범위가 여러 서비스로 확장되면 그 시점에 더 적절한 공통 이름과 구조로 변경합니다.
