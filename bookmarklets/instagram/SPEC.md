# Instagram RI — Specification

이 문서는 Instagram RI 북마클릿의 제품/UI/저장/수치/향후 확장 기준입니다.

## 1. 기준 원칙
- Instagram 원래 모바일 UI와 3열 Grid를 유지한다.
- 카드 크기·행 높이 변경, 불필요한 flicker를 만들지 않는다.
- shortcode를 저장·수치·댓글·분석의 공통 identity로 사용한다.
- missing / 미확인 값을 `0`으로 만들지 않는다.
- Instagram native action을 제거하거나 불필요하게 복제하지 않는다.
- 기능 실행 본체는 `current.js` 하나만 유지한다.
- `reels-inspector/**`는 읽기 전용 참고자료다. 북마클릿 작업에서 수정·삭제·정리·커밋하지 않는다.
- 기존 확장앱 구현은 완성본으로 간주하지 않고, 쓸 만한 계산/표시/상태 구조만 선별해 북마클릿용으로 다시 구현한다.
- 새 기능은 생길 때마다 빈 곳에 붙이지 않고, 아래 역할 레이어 중 하나에만 배치한다.

## 2. 제품 UI 상위 구조

```text
인스타그램 모바일
└─ RI 리서치 시스템
   │
   ├─ 화면 정보 레이어
   │  ├─ Grid 비교 지표
   │  ├─ Reel 핵심 지표
   │  └─ Feed 최소 지표
   │
   ├─ 빠른 작업 레이어
   │  └─ 콘텐츠별 저장 선택
   │
   ├─ 공통 진입 레이어
   │  └─ 리서치
   │
   ├─ 콘텐츠 리서치 레이어
   │  ├─ 간단 보기
   │  └─ 상세 보기
   │     ├─ 요약
   │     ├─ 콘텐츠
   │     ├─ 댓글
   │     ├─ 분석
   │     └─ 미디어
   │
   ├─ 전역 관리 레이어
   │  ├─ 저장
   │  ├─ 데이터
   │  ├─ 리서치 설정
   │  └─ 업데이트
   │
   └─ 작업 상태 레이어
      ├─ 확인
      ├─ 수집
      ├─ 저장
      ├─ 분석
      └─ 오류
```

### 레이어 역할
- **화면 정보**: 현재 Instagram 화면에서 즉시 비교해야 하는 최소 정보만 표시한다.
- **빠른 작업**: 저장처럼 한두 번의 탭으로 끝나는 작업만 담당한다.
- **공통 진입**: 현재 콘텐츠 또는 전역 리서치 창으로 들어가는 하나의 진입점이다.
- **콘텐츠 리서치**: 한 콘텐츠의 상세 정보·댓글·분석·미디어를 다룬다.
- **전역 관리**: 특정 콘텐츠에 속하지 않는 설정·데이터 관리·업데이트를 담당한다.
- **작업 상태**: 저장/수집/분석 진행과 오류를 공통 방식으로 표시한다.

## 4. 전역 리서치 구조

```text
전역 리서치 [현재 콘텐츠가 없거나 전역 관리 진입]
├─ 홈
│  ├─ 현재 콘텐츠 인식 상태
│  └─ 현재 작업
│
├─ 저장
│  ├─ 저장 방식
│  │  ├─ 기본 다운로드
│  │  ├─ 지정 폴더
│  │  └─ 매번 선택
│  ├─ 현재 폴더
│  └─ 폴더 변경
│
├─ 데이터 [향후]
│  ├─ 수집 기록
│  ├─ 저장한 콘텐츠
│  ├─ 수치 기록
│  ├─ JSON 내보내기
│  └─ CSV 내보내기
│
├─ 리서치 설정 [향후]
│  ├─ 댓글 수집
│  ├─ 음성 변환
│  ├─ 화면 글자
│  └─ 분석
│
└─ 업데이트 [하단]
   ├─ 현재 버전
   └─ 업데이트 바로가기
```

- 콘텐츠별 기능 설정을 상세 탭 안에 반복 배치하지 않는다.
- 저장/수집/분석의 전역 기본값은 전역 리서치에서 관리한다.
- 현재 Loader의 업데이트 기능은 최종적으로 전역 리서치의 `업데이트 바로가기`에서 호출한다.
- 본체가 실행되지 않는 상황의 복구 수단은 Loader 쪽에 별도로 남길 수 있다.

## 5. 작업 상태 구조

선택 UI와 작업 상태 UI를 분리한다.

```text
작업 상태
├─ 확인 중
├─ 수집 중
│  └─ 현재 / 전체
├─ 저장 중
│  └─ 현재 / 전체
├─ 분석 중
└─ 오류
   ├─ 오류 내용
   ├─ 다시 시도
   └─ 설정 열기
```

- 리서치 창이 닫혀 있으면 화면 하단의 작은 Activity/Toast로 표시한다.
- 리서치 창이 열려 있으면 같은 상태 모델을 창 내부 Activity 영역에서 표시한다.
- 저장 선택 메뉴는 저장 항목을 고르는 역할만 하고 진행률/성공/실패를 담당하지 않는다.
- 현재 상태 패널의 진단 기능은 Activity로 옮기되 오류 원인과 대상 shortcode 확인 기능은 유지한다.

## 6. 기능이 추가될 때의 배치 규칙

```text
새 기능
├─ 화면에서 즉시 비교해야 함 → 화면 정보 레이어
├─ 즉시 실행 작업임 → 빠른 작업 레이어
├─ 한 콘텐츠의 원본/수집 데이터임 → 콘텐츠 탭
├─ 댓글 원문/댓글 반응임 → 댓글 탭
├─ 해석/파생 결과임 → 분석 탭
├─ 파일/미디어 저장 관련임 → 미디어 탭
├─ 전체 설정/기록/내보내기임 → 전역 리서치
└─ 진행/오류임 → 작업 상태 레이어
```

예시:
- caption / hashtag / mention → `콘텐츠`
- STT → `콘텐츠 > 음성 내용`
- OCR → `콘텐츠 > 화면 글자`
- 댓글 원문 / 답글 → `댓글 > 원문`
- 댓글 분류 → `댓글 > 핵심 반응`
- 훅 / 구성 / CTA / 종합 해석 → `분석`
- 영상/음원/표지/사진/슬라이드 저장 → `미디어` + `빠른 저장`
- 저장 기록 / 수치 history / CSV / JSON → `전역 리서치 > 데이터`
- 저장 위치 / 분석 기본 설정 → `전역 리서치`

## 7. Grid 수치 규칙

```text
첫째 줄  조회수 | 좋아요 | 댓글 | 재게시
둘째 줄  참여율 | 24시간 | 계정대비 | 게시일
```

- 각 줄은 4개 fixed slot을 유지한다.
- 숫자 길이 때문에 slot 위치를 바꾸지 않는다.
- 같은 값이면 DOM을 다시 쓰지 않는 renderKey 방식을 사용한다.
- 사진/슬라이드의 확인되지 않은 조회수는 `-`로 표시한다.
- 실제 raw input이 없으면 숫자를 생성하지 않는다.

### 참여율
`(좋아요 + 댓글 + 재게시) / 조회수 × 100`

### 24시간
- 현재 조회수와 과거 snapshot을 사용한다.
- 18~32시간 범위의 실제 snapshot만 후보로 사용한다.
- 24시간에 가장 가까운 snapshot을 선택한다.

### 계정대비
- 같은 계정 최근 게시물의 조회수를 사용한다.
- 현재 게시물은 제외한다.
- 최대 최근 20개, 최소 5개 표본을 사용한다.
- 중앙값 대비 현재 조회수의 배수로 표시한다.

### 표시 형식
- 수치: `42.9만`, `1.2억`, `3.4K`
- 참여율: `0.55%`
- 24시간: `+8.2%`
- 계정대비: `×3.7`
- 게시일: `08/26`

## 8. 수치 저장 구조
24시간과 계정대비를 위해 북마클릿 전용 history를 사용한다.

```text
RI History
├─ 게시물 기록
│  ├─ shortcode
│  ├─ 계정명
│  ├─ 조회수
│  └─ 기록 시간
└─ 조회수 snapshot
   ├─ shortcode
   ├─ 조회수
   └─ 기록 시간
```

- `reels-inspector`의 `ri311:*` 저장 키를 공유하지 않는다.
- 북마클릿 전용 key를 사용한다.
- 기존 확장앱 데이터와 섞거나 변경하지 않는다.

## 9. 저장 규칙

### 영상 / 릴스
- `영상 저장` = 소리 포함 정상 MP4.
- `음원 저장` = 별도 음원 파일.
- `이미지 저장` = 실제 표지가 있으면 실제 표지, 없으면 정확한 0.000초 첫 표시 프레임.
- `3개 모두 저장`을 선택했을 때만 영상 + 음원 + 이미지를 모두 저장한다.
- 실시간 재생 녹화/재인코딩으로 몰래 fallback하지 않는다.

### 사진
- 원본 사진 1개를 저장한다.

### 슬라이드
- 사진 / 영상 / 혼합을 모두 지원한다.
- 원래 순서를 유지한다.
- ZIP으로 묶지 않고 개별 파일로 저장한다.

### 저장 위치
- 기본 다운로드
- 지정 폴더
- 매번 선택(단일 파일용)
- 지정 폴더 핸들은 IndexedDB에 저장하고 재실행 시 복원한다.
- 지정 폴더 실패 시 사용자 모르게 기본 다운로드로 fallback하지 않는다.

### 파일명
- 영상: `IG_{shortcode}.mp4`
- 음원: `IG_{shortcode}_a.m4a`
- 실제 표지: `IG_{shortcode}_c.{ext}`
- 첫 프레임: `IG_{shortcode}_f.jpg`
- 사진: `IG_{shortcode}.{ext}`
- 슬라이드: `IG_{shortcode}_01.{ext}`, `_02` ...

## 11. 적용 순서

```text
P0    v0.8.6 선택 저장 실기기 검증

P0.5A 화면 기반 UI
      ├─ Grid 오버레이 자리
      ├─ 콘텐츠 유형 [우측 위]
      ├─ 빠른 저장 [좌측 아래]
      └─ 공통 Activity

P0.5B 리서치 진입 / 창 골격
      ├─ 리서치 버튼
      ├─ 간단 보기
      ├─ 상세 보기
      ├─ 5개 상세 메뉴
      └─ 전역 리서치 기본 골격

P0.6  수치 Data Store + 계산
      ├─ 현재 기본 지표
      ├─ history
      ├─ 참여율
      ├─ 24시간
      └─ 계정대비

P0.7  화면 수치 연결
      ├─ Grid 8-slot
      ├─ Reel 핵심 지표
      └─ Feed 최소 지표

P1    identity / Instagram API 실패 경로 보강
P2    지정 폴더 지속성
P3    표지 / 0초 프레임 / 저장 속도 최종 검증
P4    본문 / 해시태그 / 언급 계정
P5    댓글 / 답글 / 수집 범위
P6    음성 변환 / 화면 글자
P7    콘텐츠 / 댓글 분석
P8    데이터 기록 / CSV / JSON 등 전역 관리 기능
```

- UI를 먼저 완성형 데이터로 채우지 않는다. 자리와 상태 전환을 먼저 고정하고 확인된 데이터만 순차 연결한다.
- 첫 코드 적용은 **Grid + 빠른 저장 + Activity**만 대상으로 한다.
- 그 다음에 리서치 진입/간단 보기 골격을 붙이고, 이후 수치 엔진을 연결한다.
- 기능이 추가될 때 상위 UI 구조를 다시 뒤엎지 않고 정해진 역할 레이어에 배치한다.
