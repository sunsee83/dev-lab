# Instagram RI — Specification

이 문서는 Instagram RI 북마클릿의 현재 제품 규칙과 앞으로 유지할 구현 원칙을 한곳에 모은 사양입니다. 과거 실험 방식과 폐기된 버전별 파일 구조는 포함하지 않습니다.

## 1. 제품 원칙
- Instagram 원래 3열 Grid와 native UI를 최대한 유지한다.
- 화면 크기·행 높이 변경이나 불필요한 flicker를 만들지 않는다.
- missing / 미확인 값은 0으로 취급하지 않는다.
- 콘텐츠 identity는 shortcode를 공통 키로 사용한다.
- 수집과 분석을 분리한다.
- 저장 기능 안정화를 우선하고 본문·지표·댓글·분석은 그 위에 확장한다.
- 활성 실행 본체는 항상 `current.js` 하나만 사용한다.

## 2. 실행 구조

```text
일반 실행
휴대폰 북마클릿
└─ 로컬 캐시 current.js
   └─ Blob script 실행

업데이트
RI 업데이트
└─ bridge-stable.svg
   └─ GitHub main 최신 커밋 SHA 확인
      └─ 해당 SHA의 current.js 수신
         └─ postMessage
            └─ 로컬 캐시 갱신
               └─ Blob script 실행
```

- 일반 실행에서는 외부 창을 열지 않는다.
- 업데이트 중계창은 사용자가 `RI 업데이트`를 직접 누르거나 캐시가 전혀 없을 때만 사용한다.
- 기능 업데이트는 `current.js` 내용만 교체한다.
- 버전별 실행 JS를 활성 폴더에 추가하지 않는다.

## 3. 현재 UI 구조

```text
Instagram 모바일
└─ RI
   ├─ 프로필 3열 Grid
   │  └─ 콘텐츠 카드
   │     └─ 저장 [좌측 아래]
   │        ├─ 영상 / Reel → 영상 + 음원 + 이미지
   │        ├─ 단일 사진 → 원본 사진 1개
   │        └─ 캐러셀 → 전체 원본
   │
   └─ 상태 패널
      ├─ 현재 콘텐츠
      ├─ 대상 선택
      ├─ 미디어 정보
      ├─ 저장 위치
      ├─ 저장 결과
      └─ PASS / PARTIAL / FAIL / WAIT
```

상태 패널은 UI가 바뀌더라도 유지한다. 저장 성공 여부만 보여주는 장식이 아니라 현재 대상과 오류 원인을 확인하는 진단 영역으로 사용한다.

## 4. 그리드 저장
- 3열 Grid 자동 대상 판별은 화면 중앙 행에서 **화면에 완전히 보이는 가장 왼쪽 카드**를 우선한다.
- 각 카드의 `저장` 버튼은 별도 선택 단계 없이 콘텐츠 유형을 판별하고 해당 저장 세트를 즉시 실행한다.
- 영상 / Reel 카드: 소리 포함 영상 + 음원 + 이미지 3개를 모두 저장한다.
- 단일 사진 카드: 원본 사진 1개를 저장한다.
- 캐러셀 카드: 사진 / 영상 / 혼합 여부와 관계없이 전체 원본을 원래 순서대로 저장한다.
- 그리드 저장도 현재 저장 위치 설정을 그대로 사용한다.
- 한 항목이 실패해도 가능한 나머지 저장은 계속한다.
- 결과는 동일한 상태 패널에 PASS / PARTIAL / FAIL로 남긴다.

## 5. 영상 / 음원 / 이미지 규칙

### 영상 저장
- `영상 저장`은 **소리 포함 정상 MP4**를 의미한다.
- 실시간 재생·녹화·재인코딩을 사용하지 않는다.
- Instagram의 소리 포함 완성 MP4를 직접 받아 저장한다.
- 처리 목표는 수 초, 기준 목표는 약 5초다.
- 실제 시간은 파일 크기와 네트워크 속도의 영향을 받는다.
- 완성 영상 직접 저장이 불가능하면 느린 재인코딩으로 몰래 대체하지 않고 오류 상태로 표시한다.

### 음원 저장
- `음원 저장`은 별도 음원 파일을 저장한다.
- 무음 영상 트랙은 내부 처리용일 뿐 일반 UI 기능으로 노출하지 않는다.

### 이미지 저장
- 명시적 실제 표지가 있으면 해당 원본 표지를 저장한다.
- 실제 표지가 없을 때만 영상 **0.000초 첫 표시 프레임**을 생성해 저장한다.
- 임의의 중간 장면, 선명한 장면, 대표 장면을 자동 선택하지 않는다.

## 6. 사진 / 캐러셀 규칙

### 단일 사진
- 원본 사진 1개를 저장한다.

### 캐러셀
- 사진 / 영상 / 혼합 캐러셀을 모두 지원한다.
- 원래 순서를 유지한다.
- 영상 슬라이드는 소리 포함 완성 영상을 저장한다.
- 전체 저장은 최대 3개 항목을 병렬로 받아 불필요한 대기 시간을 줄인다.
- `매번 선택` 모드는 캐러셀 전체 저장에 사용하지 않는다. 기본 다운로드 또는 지정 폴더를 사용한다.

## 7. 저장 위치
- 기본 다운로드
- 지정 폴더
- 매번 선택(브라우저 지원 시, 단일 파일 저장용)
- 지정 폴더 핸들은 IndexedDB에 저장한다.
- 재실행 시 저장된 폴더 핸들을 복원한다.
- 권한이 만료된 경우 저장 시 쓰기 권한을 다시 요청한다.
- 그리드 저장과 개별 저장은 같은 저장 위치 설정을 공유한다.

## 8. 파일명 규칙
shortcode 자체가 게시물 고유 식별자이므로 계정명은 파일명에서 제외한다.

- 영상: `IG_{shortcode}.mp4`
- 음원: `IG_{shortcode}_a.m4a`
- 실제 표지: `IG_{shortcode}_c.{ext}`
- 표지 없는 영상 첫 프레임: `IG_{shortcode}_f.jpg`
- 단일 사진: `IG_{shortcode}.{ext}`
- 캐러셀: `IG_{shortcode}_01.{ext}`, `IG_{shortcode}_02.{ext}` ...
- 캐러셀 영상 항목은 같은 순번에 `.mp4`를 사용한다.

한 게시물의 저장 파일은 같은 shortcode를 공유해야 한다.

## 10. 향후 제품 구조

```text
리서치 UI
├─ Grid
│  ├─ 콘텐츠 유형
│  ├─ 기본 지표
│  ├─ 파생 지표
│  └─ 빠른 저장
├─ Reel
│  └─ native action을 침범하지 않는 리서치 지표
└─ Research Workspace
   ├─ 요약
   ├─ 콘텐츠
   ├─ 댓글
   ├─ 분석
   └─ 미디어
```

## 11. 개발 순서

```text
Phase 1  저장 안정화
├─ 영상
├─ 음원
├─ 이미지 / 첫 프레임
├─ 사진
├─ 캐러셀 전체
├─ 그리드 빠른 저장
├─ 지정 폴더
└─ 파일명 / identity 검증

Phase 2  콘텐츠 데이터
├─ caption
├─ hashtags / mentions
├─ 게시일 / 작성자
└─ 공개 metrics

Phase 3  댓글
├─ 댓글
├─ 답글
├─ 중복 제거
└─ 수집 범위 표시

Phase 4  리서치 분석
├─ STT
├─ OCR
├─ 댓글 분류
└─ 콘텐츠 분석
```

Phase 1이 실제 Android Edge에서 안정적으로 통과하기 전에는 이후 기능 때문에 저장 경로를 복잡하게 만들지 않는다.
