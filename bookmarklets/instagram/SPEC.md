# Instagram RI — Specification

현재 UI 기준: **v0.9.5**

이 문서는 Instagram 모바일 웹용 RI 북마클릿의 제품 구조, UI, 저장, 수치, 데이터, 검증 기준을 정의한다.

## 1. 제품 원칙

RI는 Instagram 위에 별도 앱을 덮는 도구가 아니다.

핵심 원칙:

1. **Instagram 콘텐츠가 항상 1순위**다.
2. RI는 필요한 순간에만 드러난다.
3. 기본 UI는 작고, 상세 UI는 사용자가 명시적으로 열 때만 확장한다.
4. 기능이 없거나 데이터가 없으면 화면을 placeholder로 채우지 않는다.
5. 개발용 진단 상태를 일반 사용자 기본 화면에 노출하지 않는다.
6. Instagram native UI를 제거하거나 재배치하지 않는다.
7. Grid 카드 크기, 행 높이, 3-column 구조를 변경하지 않는다.
8. 저장, 수치, 댓글, 분석은 shortcode를 공통 identity로 사용한다.
9. 실기기 확인 전 PASS 처리하지 않는다.
10. `reels-inspector/**`는 읽기 전용 참고자료다.

## 2. 파일 / 런타임 원칙

활성 파일은 정확히 5개다.

```text
bookmarklets/instagram/
├─ README.md
├─ SPEC.md
├─ bookmarklet-url.txt
├─ bridge-stable.svg
└─ current.js
```

- archive, 임시 파일, 버전 복사본을 만들지 않는다.
- 과거 버전은 Git history로 관리한다.
- `current.js`는 평문 JS 본체를 유지한다.
- 북마크 주소는 기능 업데이트마다 교체하지 않는다.
- Loader는 최신 `current.js` 수신 / 캐시 교체 / 실행을 담당한다.
- 본체 정상 실행 시 Loader의 별도 업데이트 버튼은 숨긴다.
- 본체 실행 실패 시에만 Loader 업데이트 버튼을 비상 복구용으로 사용한다.

보안상 GitHub 또는 bookmark URL에 저장하지 않는 값:

- API key
- password
- login token
- access / refresh token
- session cookie
- 인증 세션 값

## 4. 시각 우선순위

화면에서의 우선순위는 다음 순서다.

```text
Instagram 콘텐츠
> 실제 수치 / 실제 연구 결과
> 현재 작업
> 저장
> 상세 리서치
> 설정 / 진단
```

따라서 다음 UI는 기본 화면에서 금지한다.

- PASS / WAIT / FAIL 목록
- 큰 진단 패널
- 전체 설정 버튼 일괄 노출
- 의미 없는 `-` 수치
- 미구현 기능의 큰 빈 화면
- 지속적인 하단 Activity / Toast

## 5. 공통 RI launcher

### 기본

- 작은 원형 `RI` 버튼
- 우측 하단 안전영역
- 반투명 배경
- 콘텐츠보다 먼저 눈에 띄지 않는 대비
- 하단 navigation / 앱 배너 침범 금지

### Reel

Instagram 기본 우측 action rail은 절대 건드리지 않는다.

Reel 화면에서 RI launcher는 우측 rail과 분리해 **좌측 안전영역**으로 이동한다.

### Sheet가 열렸을 때

- launcher는 숨긴다.
- sheet를 닫으면 launcher를 다시 표시한다.

## 6. Grid UI

### DOM 구조

Grid UI는 반드시 Instagram 카드 anchor 내부에 직접 부착한다.

```text
Instagram card anchor [position: relative]
└─ RI card UI [absolute inset: 0]
   ├─ quick save
   └─ metrics [실제 값이 있을 때만]
```

금지:

- fixed global card overlay
- 스크롤 시 카드 좌표 재계산으로 UI 이동
- 카드 행 높이 변경
- 원본 Grid 폭 변경
- 과도한 DOM style mutation

Instagram SPA가 카드 DOM을 재사용할 수 있으므로:

- 가벼운 재스캔 허용
- 현재 유효한 Grid anchor 목록 재판정
- 더 이상 Grid 카드가 아닌 anchor의 RI UI 제거
- 클릭 순간 현재 `href`에서 shortcode 재해석

### Grid quick save

위치:

- 카드 좌측 상단

시각:

- 작은 원형 touch target
- 단순 다운로드 SVG
- 얇은 테두리
- 약한 반투명 배경
- 썸네일 내용을 가리지 않는 크기

상태:

```text
기본 → 다운로드 아이콘
진행 → …
성공 → ✓
실패 → !
```

일정 시간이 지나면 기본 아이콘으로 복귀한다.

### Grid metrics

실제 수치 엔진이 연결되기 전에는 영역 전체를 숨긴다.

최종 8-slot:

```text
1행: 조회수 | 좋아요 | 댓글 | 재게시
2행: 참여율 | 24시간 | 계정대비 | 게시일
```

표시 규칙:

- 카드 내부 하단 gradient
- 2행 × 4칸 고정 슬롯
- tabular numbers
- 강한 text shadow / stroke
- 고정 슬롯 폭
- missing 값은 `0`이나 `-`로 생성하지 않음

## 7. Grid 저장 메뉴

Grid quick save를 누를 때만 해당 버튼 가까이에 작은 floating menu를 연다.

Reel / 영상:

```text
영상      음원
이미지    3개 모두
```

사진:

```text
원본 사진
```

슬라이드:

```text
슬라이드 전체
```

메뉴 규칙:

- 화면 중앙 modal 금지
- 전체 화면 dim 금지
- Instagram 하단 navigation 영역 침범 금지
- 사용자가 선택하면 즉시 닫힘
- 저장 상태는 원래 quick save 버튼에 표시

## 8. RI 간단 보기

기본 RI는 큰 panel이 아니라 **작은 command sheet**다.

구조:

```text
@계정명 · 유형           •••   상세   ×

저장                         저장 방식
```

### Header

좌측:

- 계정명
- 콘텐츠 유형

우측:

- `•••` 관리
- `상세`
- 닫기

### Body

- 대표 작업은 `저장` 하나
- 현재 저장 방식은 작은 보조 텍스트
- 데이터가 아직 없으면 수치 영역을 만들지 않음
- 작업 중일 때만 작은 activity row 추가

간단 보기의 목적은 Instagram 감상을 크게 방해하지 않고 현재 콘텐츠의 핵심 진입점만 제공하는 것이다.

## 9. RI 저장 선택

간단 보기의 `저장` 버튼을 누르면 Grid와 같은 compact floating menu를 사용한다.

영상 / Reel:

- 영상
- 음원
- 이미지
- 3개 모두

사진:

- 원본 사진

슬라이드:

- 슬라이드 전체

큰 3-button panel을 기본 sheet에 상시 노출하지 않는다.

## 10. RI 관리 메뉴

`•••`는 설정 페이지가 아니라 전역 관리 entry다.

목록 구조:

```text
관리
├─ 저장
├─ 데이터               [미연결 시 준비 중]
└─ 리서치 설정          [미연결 시 준비 중]

시스템
├─ 업데이트
├─ 진단 복사
└─ RI 종료
```

버튼 타일 2×3 / 3×2 구조를 기본으로 사용하지 않는다.

목록형 UI 원칙:

- 좌측 작은 icon area
- 중앙 label + 설명
- 우측 현재 값 또는 상태
- 하위 화면이 있으면 chevron
- 미구현 항목은 disabled 상태로 짧게 표시

## 11. 저장 방식 하위 화면

`관리 > 저장`에서만 다음을 보여준다.

```text
기본 다운로드
지정 폴더
매번 선택
```

현재 선택된 방식에는 check 표시.

지정 폴더 handle이 있으면 폴더명을 함께 표시할 수 있다.

## 12. 상세 보기

상세는 사용자가 `상세`를 눌렀을 때만 열린다.

상단 tabs:

```text
요약 | 콘텐츠 | 댓글 | 분석 | 미디어
```

### 상세 sheet 원칙

- 전체 화면을 무조건 채우지 않는다.
- 실제 콘텐츠 높이만큼 사용하고 상한만 둔다.
- 미수집 상태는 짧은 설명 card로 표현한다.
- 큰 빈 검은 영역 금지.
- 각 탭의 역할은 기능 연결 전에도 명확하게 보이게 한다.

### 요약

향후 표시:

- 기본 성과
- 파생 성과
- 콘텐츠 identity
- 데이터 상태
- 다른 탭 핵심 결과

현재 데이터가 없다면:

- 계정 / 유형 / shortcode
- 저장 방식
- 리서치 데이터 미수집 상태

정도만 표시한다.

### 콘텐츠

향후:

- 전체 본문
- 해시태그
- 언급 계정
- STT 전체
- 시간대별 음성 문장
- OCR 문구
- OCR 표시 시간 / 위치

### 댓글

향후:

- 전체 댓글 수
- 실제 수집 댓글 수
- 답글 수
- 질문
- 구매의도
- 긍정
- 부정 / 불만
- 반론
- 팁 / 정보
- 원문 / 답글

### 분석

향후:

- 시작 훅
- 첫 핵심 메시지
- 도입
- 전개
- 핵심
- 마무리
- CTA
- 강조 문구
- 숫자
- 가격
- 성과 특징
- 콘텐츠 특징
- 댓글 반응 특징

### 미디어

콘텐츠 유형에 맞는 저장 작업만 표시한다.

영상:

- 영상
- 음원
- 이미지

사진:

- 원본 사진

슬라이드:

- 슬라이드 전체

## 13. Reel 핵심 지표

Instagram 기본 우측 action rail은 그대로 둔다.

RI 핵심 지표는 영상 영역 좌측 하단 / 본문 위의 안전영역을 사용한다.

표시 대상:

- 조회수
- 참여율
- 24시간
- 계정대비
- 게시일

실제 값이 없으면 placeholder를 만들지 않는다.

## 14. Feed / Post

Instagram 기본 UI 유지.

성과정보 인접 위치에 최소 추가 지표만 표시한다.

- 참여율
- 24시간
- 계정대비
- 게시일

Feed에 별도의 큰 RI panel을 상시 추가하지 않는다.

## 15. 알림 / 작업 상태

기본 화면 하단에 지속적인 Activity / Toast를 띄우지 않는다.

`AbortError`:

- 파일 선택 취소
- 폴더 선택 취소

사용자가 취소한 정상 동작이므로 **무알림** 처리한다.

작업 상태 위치:

```text
Grid 저장 → 해당 카드 quick save
RI 열림 → RI sheet 내부
실제 오류 → 상단 작은 임시 알림
```

## 16. 저장 규칙

### Reel / 영상

사용자 선택:

- 영상
- 음원
- 이미지
- 3개 모두

Grid 저장 버튼을 눌렀다고 자동으로 3개를 전부 저장하지 않는다.

### 영상 성공 기준

- 실제 MP4
- 소리 포함
- 정상 재생

무음 MP4는 성공이 아니다.

MediaRecorder / 실시간 재녹화 방식은 사용하지 않는다.

직접 미디어 다운로드를 우선한다.

### 이미지 / 표지

1. Instagram explicit cover가 있으면 실제 cover 저장
2. 없으면 영상의 정확한 `0.000초` 첫 표시 프레임 생성

대표 2초 프레임 등 임의 프레임 금지.

### 사진

- 원본 사진 저장

### 슬라이드

- 전체 원본 개별 저장

### 목표 속도

직접 미디어 다운로드 기준 수 초 수준을 목표로 한다.
영상 길이만큼 기다리는 녹화 방식은 금지한다.

## 17. 저장 모드

지원:

- 기본 다운로드
- 지정 폴더
- 매번 선택

지정 폴더 handle은 북마클릿 전용 IndexedDB에 저장한다.

확장앱 저장공간과 공유하지 않는다.

## 18. 데이터 저장 구조

북마클릿 전용 storage 사용.

최소 구조:

```text
shortcode
├─ current
│  ├─ username
│  ├─ type
│  ├─ postedAt
│  ├─ views
│  ├─ likes
│  ├─ comments
│  └─ reposts
│
├─ history
│  └─ view snapshots
│
└─ source / status
```

Verified Store 전체를 초기 이식하지 않는다.
필요한 최소 conflict / source 규칙만 추가한다.

## 19. 수치 계산

### 참여율 ER

```text
(좋아요 + 댓글 + 재게시) / 조회수 × 100
```

### 24시간

실제 snapshot 중 18~32시간 범위에서 24시간에 가장 가까운 기록 사용.

### 계정대비

같은 계정 최근 게시물:

- 최대 20개
- 최소 5개
- 조회수 중앙값

현재 조회수 / 최근 조회수 중앙값 배수로 계산한다.

중요:

- 데이터가 없으면 0을 만들지 않는다.
- missing / 확인 중 / 값 없음 상태로 유지한다.

## 20. 전역 RI 향후 구조

현재 콘텐츠가 없을 때 전역 RI를 사용한다.

```text
전역 RI
├─ 홈
│  ├─ 현재 콘텐츠 인식
│  └─ 현재 작업
├─ 저장
│  ├─ 기본 다운로드
│  ├─ 지정 폴더
│  ├─ 매번 선택
│  └─ 현재 폴더
├─ 데이터
│  ├─ 수집 기록
│  ├─ 저장 콘텐츠
│  ├─ History
│  ├─ JSON
│  └─ CSV
├─ 리서치 설정
│  ├─ 댓글
│  ├─ STT
│  ├─ OCR
│  └─ 분석
└─ 업데이트
   ├─ 현재 버전
   └─ 업데이트
```

## 21. 우선순위

### P0.5

UI 실기기 확정.

- Grid quick save
- RI launcher
- 간단 보기
- 저장 floating menu
- 관리 목록
- 상세 tabs

기능 추가보다 UI 완성도를 우선한다.

### P0.6

수치 저장 / 계산.

### P0.7

Grid / Reel / Feed 실제 수치 연결.

### P1 이후

- Instagram 콘텐츠 인식 / API fallback
