# Instagram RI Bookmarklet

현재 활성 버전: **v0.9.7**

## 활성 파일

```text
bookmarklets/instagram/
├─ README.md
├─ SPEC.md
├─ bookmarklet-url.txt
├─ bridge-stable.svg
└─ current.js
```

활성 파일은 정확히 5개만 유지한다. 과거 버전은 Git history로 관리한다.

`reels-inspector/**`는 읽기 전용 참고자료다. 수정·삭제·정리·커밋하지 않는다.

## 실행 / 업데이트

- `current.js`는 평문 JS 본체를 유지한다.
- `RI 업데이트`가 GitHub 최신 본체를 받아 캐시를 교체한다.
- 기능 업데이트마다 북마크 주소를 교체하지 않는다.
- 본체 정상 실행 시 Loader 업데이트 버튼은 숨긴다.
- 본체 실행 실패 때만 Loader 버튼을 비상 복구용으로 사용한다.

## 저장 엔진 기준

Android Edge 실기기에서 이전에 확인된 기반 기능:

- Reel 소리 포함 영상 저장
- Reel 음원 단독 저장
- Reel 이미지 저장
- 단일 사진 원본 저장
- 캐러셀 전체 개별 저장
- 기본 다운로드 / 지정 폴더 / 매번 선택
- shortcode 기반 짧은 파일명
- MediaRecorder 실시간 재인코딩 사용 안 함

영상 저장 성공은 **소리 포함 정상 MP4** 기준이다.

## v0.9.6 실기기 스크린샷에서 확인된 UI 문제

### Grid

수치 UI는 다시 나타났지만 표현 규칙에 오류가 있었다.

- 조회수 값이 없는데 `▶` 아이콘만 남음
- 재게시 값이 없는데 `↻` 아이콘만 남음
- 즉, missing 값은 빈 슬롯이어야 하는데 아이콘만 placeholder처럼 노출됨
- Grid 저장 버튼이 3-column 카드 대비 아직 크게 보임
- 하단 gradient와 숫자 밀도가 조금 강해 썸네일보다 RI가 먼저 보이는 카드가 있음

원인은 `metricRows()`에서 값 존재 여부와 관계없이 아이콘 문자열을 먼저 생성한 것이다.

### RI 간단 보기

- 150px CSS 높이는 실제 모바일 화면에서는 여전히 큰 검은 영역으로 느껴짐
- grabber + header + 수치 + 저장방식 + action을 모두 펼쳐 기본 화면이 답답함
- 조회/ER 등이 없고 게시일만 있을 때 `08/14 · 게시`가 핵심 수치처럼 크게 노출됨
- `매번 선택` 같은 저장 방식 텍스트가 primary action과 상세 버튼 사이를 차지해 정보 계층이 흐려짐

### 상세 보기

- `height: 68vh` 고정 때문에 실제 내용보다 sheet가 훨씬 크게 남음
- 요약 내용이 끝난 뒤에도 검은 빈 공간이 계속 이어짐
- 콘텐츠 / 댓글 / 분석 / 미디어 탭은 구조는 생겼지만 동일한 density와 상태표현 규칙을 더 정리할 필요가 있음

### Reel

- 실제 성과 수치 없이 게시일만 확보된 경우 `게시 08/26` overlay가 홀로 노출됨
- RI launcher가 research SVG라 일반 사용자가 기능을 바로 이해하기 어려움

## v0.9.7 — UI 밀도 / missing / sheet 구조 수정

v0.9.7은 저장 엔진을 다시 만드는 버전이 아니라 **실기기 스크린샷에서 드러난 UI 원인을 수정하는 버전**이다.

### 1. Grid 수치

`reels-inspector`의 2행 × 4칸 구조는 계속 유지한다.

```text
1행: ▶조회수 | ♥좋아요 | ●댓글 | ↻재게시
2행: 참여율 | 24시간 | 계정대비 | 게시일
```

수정 사항:

- 값이 있을 때만 해당 아이콘 + 숫자를 생성
- 조회수 missing → `▶` 자체도 표시하지 않음
- 재게시 missing → `↻` 자체도 표시하지 않음
- 좋아요 / 댓글도 같은 규칙 적용
- 실제 성과값이 하나도 없으면 Grid metrics 전체 숨김
- 게시일 하나만 있는 카드는 metrics 전체를 띄우지 않음
- 슬롯 폭은 고정 유지
- `tabular-nums` 유지
- 1행 shadow / 2행 stroke 유지

Grid 저장 버튼:

- 27px → **24px**
- 내부 SVG 14px
- 배경 / 테두리 대비를 더 낮춤
- 카드 좌측 상단 DOM attachment 방식은 그대로 유지

### 2. RI 간단 보기

기본 sheet를 다시 줄였다.

- edge-to-edge 대형 sheet 대신 좌우 8px 여백의 작은 bottom dock
- compact mode에서는 grabber 숨김
- header 34px
- action 34px
- 최대 높이 118px
- 실제 수치가 없으면 수치 strip 자체가 없어져 더 낮아짐
- 저장 방식 텍스트는 기본 화면에서 제거
- 저장 / 상세 / 관리만 유지

핵심 수치 strip은 실제 확보된 값에서 최대 4개만 보여준다.

우선순위:

```text
조회 → 좋아요 → 댓글 → ER → 24h → 계정대비
```

게시일은 KPI strip이 아니라 header의 작은 metadata로 이동한다.

### 3. 상세 Research UI

고정 `68vh` 높이를 제거했다.

- `height: auto`
- 최대 높이만 72vh로 제한
- 실제 내용 높이만큼만 sheet가 열림
- 내용이 많을 때 body만 스크롤
- 요약이 짧으면 큰 검은 빈 공간이 남지 않음

요약 탭:

- 게시일을 성과 KPI에서 제외하고 콘텐츠 정보로 이동
- 성과 KPI는 실제 성과값만 표시
- 조회 / 좋아요 / 댓글 / 재게시 / ER / 24h / 계정대비

콘텐츠 탭:

- 본문 / 해시태그 / 언급
- STT / 타임라인
- OCR / 시간 / 위치

댓글 탭:

- 실제 전체댓글 값이 있을 때만 summary 표시
- 수집 / 답글 미연결 값을 `—`로 만들지 않음
- 반응 분류 / 원문·답글 영역은 작은 상태 card로 유지

분석 탭:

- 시작부
- 구성
- 표현 / 전환

미디어 탭:

- 콘텐츠 유형에 맞는 저장 작업만 표시

### 4. Reel UI

- 조회 / ER / 24h / 계정대비 중 실제 성과값이 하나도 없으면 overlay 전체 숨김
- 게시일만 단독으로 표시하지 않음
- 성과값이 하나 이상 있을 때만 게시일을 보조 정보로 함께 표시
- launcher는 추상적인 research SVG 대신 **작은 `RI` 원형 버튼**으로 변경
- Instagram 우측 action rail은 건드리지 않음

### 5. 전역 관리

구조는 유지한다.

```text
관리
├─ 저장
├─ 데이터
├─ 리서치 설정
└─ 업데이트

시스템
├─ 진단 복사
└─ RI 종료
```

기본 콘텐츠 화면에는 전역 관리 기능을 펼쳐놓지 않는다.

## Grid 수치 저장 / 계산

북마클릿 전용 `localStorage`만 사용한다.

최소 구조:

```text
shortcode
├─ username
├─ type
├─ postedAt
├─ views
├─ likes
├─ comments
├─ reposts
├─ updatedAt
└─ history[]
```

파생 지표:

- 참여율: `(좋아요 + 댓글 + 재게시) / 조회수 × 100`
- 24시간: 18~32시간 snapshot 중 24시간에 가장 가까운 기록
- 계정대비: 같은 계정 최근 최대 20개 / 최소 5개 조회수 중앙값 대비
- 조건이 부족하면 missing으로 유지

## 알림 정책

- 지속적인 하단 Activity / Toast 금지
- `AbortError`는 정상 취소이므로 무알림
- Grid 저장 진행은 해당 카드 버튼에서 표시
- RI sheet가 열려 있으면 상태는 sheet 내부 표시
- 실제 오류만 상단에 짧게 표시
