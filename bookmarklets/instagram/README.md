# Instagram RI Bookmarklet

현재 활성 버전: **v0.9.5**

## 활성 파일

```text
bookmarklets/instagram/
├─ current.js
├─ bridge-stable.svg
├─ bookmarklet-url.txt
├─ README.md
└─ SPEC.md
```

활성 파일은 위 5개만 유지한다. 과거 버전은 Git history로 관리한다.

`reels-inspector/**`는 읽기 전용 참고자료다. 수정·삭제·정리·커밋하지 않는다.

## 실행 / 업데이트

- 일반 실행은 휴대폰에 캐시된 `current.js`를 실행한다.
- 사용자가 `RI 업데이트`를 누르면 GitHub의 최신 `current.js`를 받아 캐시를 교체한다.
- 정상적인 기능 업데이트마다 북마크 주소를 다시 바꾸지 않는다.
- 본체가 정상 실행되면 Loader의 별도 업데이트 버튼은 숨긴다.
- 본체 실행 실패 때만 Loader 버튼을 비상 복구용으로 사용한다.
- `current.js`는 압축 Base64 wrapper가 아닌 평문 JS 본체를 유지한다.

## 저장 엔진 기준

기존 실기기 확인 기반 기능:

- Reel 소리 포함 영상 저장
- Reel 음원 단독 저장
- Reel 이미지 저장
- 단일 사진 원본 저장
- 캐러셀 전체 개별 저장
- 기본 다운로드 / 지정 폴더 / 매번 선택
- shortcode 기반 짧은 파일명
- 실시간 MediaRecorder 재인코딩 사용 안 함

영상 저장 성공은 **소리 포함 정상 MP4** 기준이다.

## v0.9.5 — UI 시스템 재설계

v0.9.5는 기능 추가 버전이 아니라 **UI 완성도 우선 버전**이다.

기존 화면의 문제:

- Grid 다운로드 버튼과 RI 버튼이 너무 강하게 보여 Instagram 콘텐츠보다 RI가 먼저 보임
- 간단 보기가 실제로는 큰 버튼 패널처럼 보임
- 설정 화면이 2×3 대형 버튼 구조라 화면을 많이 가림
- 상세 화면에 데이터가 없는데도 큰 검은 빈 영역이 생김
- 저장 / 상세 / 설정 / 진단이 같은 시각적 중요도로 노출됨
- 개발 도구 같은 인상이 강하고 모바일 제품 UI의 계층이 부족함

v0.9.5부터 UI를 아래 원칙으로 고정한다.

### 1. 평상시 화면

Instagram 콘텐츠가 항상 1순위다.

화면에 지속적으로 보이는 RI 요소는 최소화한다.

- Grid 카드: 작은 저장 아이콘
- 공통 진입: 작은 `RI` 버튼
- 수치가 없으면 Grid 지표 영역 자체를 숨김
- 하단 Activity / 개발 상태 패널 없음

### 2. Grid 저장 아이콘

- 카드 DOM 내부 `absolute` 부착 유지
- fixed global overlay 사용 금지
- 카드 크기 / 행 높이 변경 금지
- 좌측 상단에 작고 약한 원형 아이콘
- 텍스트 `↓` 대신 단순 다운로드 SVG 사용
- 반투명 배경 + 얇은 테두리
- 실제 저장 진행 시 해당 아이콘만 `… → ✓ / !` 상태 표시
- Instagram SPA가 anchor를 재사용하면 현재 유효하지 않은 RI UI를 제거하고 다시 부착
- 클릭 순간 현재 anchor `href`에서 shortcode를 다시 읽음

### 3. RI 간단 보기

기본 RI는 **작은 command sheet**다.

```text
@계정명 · 콘텐츠유형      •••   상세   ×

저장                         현재 저장 방식
```

원칙:

- 큰 3개 저장 버튼을 기본 화면에 펼쳐두지 않음
- 기본 높이는 콘텐츠 감상을 방해하지 않는 수준으로 제한
- 현재 계정 / 콘텐츠 유형만 짧게 표시
- 저장은 1개의 대표 버튼으로 진입
- 현재 저장 방식은 작은 보조 텍스트로 표시
- 작업 중일 때만 sheet 내부에 작은 상태 행 표시

### 4. 저장 선택 UI

`저장`을 눌렀을 때만 작은 floating menu가 나타난다.

영상 / Reel:

```text
영상      음원
이미지    3개 모두
```

사진:

```text
원본 사진
```

슬라이드:

```text
슬라이드 전체
```

Grid와 RI sheet 모두 같은 저장 선택 개념을 사용한다.

### 5. RI 관리 메뉴

기존 2×3 대형 설정 버튼을 제거하고 **목록형 정보 구조**로 변경한다.

```text
RI
├─ 관리
│  ├─ 저장
│  ├─ 데이터          [준비 중]
│  └─ 리서치 설정     [준비 중]
└─ 시스템
   ├─ 업데이트
   ├─ 진단 복사
   └─ RI 종료
```

저장 방식을 선택할 때만 하위 화면에서 다음을 보여준다.

- 기본 다운로드
- 지정 폴더
- 매번 선택

### 6. 상세 보기

상세는 사용자가 `상세`를 눌렀을 때만 열린다.

상단 탭:

```text
요약 | 콘텐츠 | 댓글 | 분석 | 미디어
```

데이터가 아직 연결되지 않은 탭도 큰 빈 패널을 만들지 않는다.
각 탭은 역할이 보이는 짧은 카드와 상태 문구만 표시한다.

요약:

- 현재 콘텐츠 identity
- 실제 수치가 연결될 영역
- 현재 저장 방식 / 데이터 상태

콘텐츠:

- 본문 / 해시태그 / 언급 계정
- STT / OCR 영역

댓글:

- 댓글 리서치 영역

분석:

- 훅 / 구성 / CTA / 반응 분석 영역

미디어:

- 현재 콘텐츠 유형에 맞는 저장 작업

### 7. RI 버튼

- 기본 화면에서는 우측 하단 안전영역에 작게 표시
- Reel에서는 Instagram 우측 action rail을 피해서 좌측으로 이동
- RI sheet가 열리면 뒤쪽 launcher는 숨김
- sheet를 닫으면 launcher가 다시 나타남

### 8. 시각 계층

UI 우선순위는 다음 순서로 고정한다.

```text
Instagram 콘텐츠
> 실제 데이터
> 현재 작업
> 저장
> 상세 리서치
> 설정 / 진단
```

따라서 진단, 업데이트, 미구현 기능은 기본 화면에 노출하지 않는다.

## 알림 정책

- 지속적인 하단 Activity / Toast 금지
- `AbortError`는 사용자가 파일/폴더 선택을 취소한 정상 동작이므로 무알림
- Grid 작업 상태는 해당 카드 버튼에서 표시
- RI sheet가 열려 있으면 작업 상태는 sheet 내부 표시
- 실제 오류만 상단에 작은 임시 알림

## Grid 수치 UI

수치 엔진이 연결되기 전에는 아무 placeholder도 보여주지 않는다.

최종 8-slot 구조:

```text
조회수 | 좋아요 | 댓글 | 재게시
참여율 | 24시간 | 계정대비 | 게시일
```

데이터가 없으면 `0` 또는 `-`를 만들어 채우지 않는다.

## 다음 실기기 확인

v0.9.5 업데이트 후 **UI만 본다. 저장 기능 테스트는 섞지 않는다.**

확인 대상:

1. Grid 화면
2. Reel 화면
3. RI 간단 보기
4. `•••` 관리 화면
5. `상세` 화면

판정 기준은 기능 유무가 아니라 다음이다.

- Instagram 콘텐츠보다 RI가 먼저 눈에 띄지 않는가
- 화면을 답답하게 가리지 않는가
- 어떤 버튼이 중요한지 바로 이해되는가
- 저장 / 상세 / 관리 역할이 섞이지 않는가
- 개발 패널이 아니라 실제 모바일 제품 UI처럼 보이는가

## 실기기 완료 기준

- Instagram 원래 3열 Grid가 변하지 않는다.
- Grid UI가 카드와 분리되어 흔들리지 않는다.
- 하단 navigation 위로 Grid 버튼이 튀어나오지 않는다.
- Reel 우측 native action rail을 침범하지 않는다.
- RI 기본 화면이 콘텐츠 감상을 과도하게 가리지 않는다.
- 데이터가 없을 때 placeholder로 화면을 채우지 않는다.
- 사용자가 취소한 작업은 오류처럼 보이지 않는다.
- 영상은 소리 포함 정상 재생된다.
