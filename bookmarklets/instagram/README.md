# Instagram RI Bookmarklet

현재 활성 버전: **v0.8.9**

## 활성 파일

```text
bookmarklets/instagram/
├─ current.js
├─ bridge-stable.svg
├─ bookmarklet-url.txt
├─ README.md
└─ SPEC.md
```

이 5개만 활성 파일로 유지한다. 과거 버전은 Git 기록으로 확인한다.

## 실행 / 업데이트
- 일반 실행은 휴대폰에 캐시된 `current.js`를 바로 실행한다.
- 일반 실행에서는 업데이트용 외부 창을 열지 않는다.
- 최신 확인은 사용자가 `RI 업데이트`를 눌렀을 때만 수행한다.
- 북마크 주소는 정상적인 기능 업데이트마다 다시 교체하지 않는다.
- `bookmarklet-url.txt`의 Loader는 캐시 실행과 `window.__RI_LOADER_REFRESH` 업데이트 함수만 제공한다.
- 본체가 정상 실행되면 Loader의 떠 있는 `RI 업데이트` 버튼은 숨기고 본체 UI에서 업데이트 함수를 호출한다.
- 본체가 실행되지 못한 경우에만 Loader 버튼이 비상 복구 진입점으로 남는다.
- 정상적인 기능 수정은 `current.js`만 갱신한다.

## v0.8.8 / v0.8.9 업데이트 장애 원인
v0.8.5에서 큰 진단 패널과 Loader의 `RI 업데이트` 버튼이 동일한 최상위 z-index를 사용했고, 본체 패널이 나중에 DOM에 추가되어 업데이트 버튼을 가리는 문제가 있었다. 스크린샷에서 패널을 접은 뒤 Loader 업데이트 버튼과 v0.8.7 본체가 동시에 보이는 것으로 이 충돌을 확인했다.

v0.8.8에서는 업데이트 버튼 소유권을 본체 UI로 옮겼지만, Android Edge에서 압축 본체를 `new Response(decompressedStream).text()`로 변환하는 단계가 `Failed to fetch`로 실패했다. gzip 데이터 자체는 로컬 검증에서 정상이고 원본 소스와 완전히 일치했다.

v0.8.9에서는:
- `Response(stream).text()` 경로를 제거했다.
- `DecompressionStream('gzip')` 출력 스트림을 `getReader()`로 직접 읽는다.
- 읽은 바이트를 `TextDecoder`로 변환한 뒤 Blob script로 실행한다.
- 본체 실행 성공 시 Loader의 별도 업데이트 버튼을 숨긴다.
- 임시 관리 패널의 `저장 위치 · 기타` 안에 `RI 업데이트`를 제공한다.
- 본체 실행 실패 시 Loader 버튼은 비상 복구 진입점으로 그대로 남는다.
- 북마크 주소 교체 없이 기존 Loader에서 최신 `current.js`를 받을 수 있어야 한다.

## 확장앱 참고 원칙
- `reels-inspector/**`는 읽기 전용 참고자료다.
- 해당 폴더의 코드·문서·테스트를 수정하거나 삭제하지 않는다.
- 완성 제품으로 간주하지 않고 계산식·UI 구조·상태 처리 중 필요한 부분만 참고한다.
- 북마클릿은 별도 런타임과 별도 저장공간을 사용한다.

## 현재 확인된 저장 동작
아래는 v0.8.7 이전까지 실제 기기에서 확인된 저장 엔진 기준이다.
- Reel 소리 포함 영상 저장
- Reel 음원 단독 저장
- Reel 이미지 저장
- 단일 사진 원본 저장
- 캐러셀 전체 개별 저장
- 기본 다운로드
- 지정 폴더 저장
- shortcode 중심 파일명
- 실시간 재인코딩 없이 영상 저장

## P0.5A UI 골격
- Grid 자체 DOM 레이아웃을 바꾸지 않고 별도 overlay layer를 사용한다.
- 콘텐츠 유형 [우측 위]
- 빠른 저장 [좌측 아래 · 지표 바로 위]
- Grid 하단 2행 × 4칸 수치 자리
- 수치는 아직 연결하지 않고 missing 자리만 표시한다.
- Grid `저장`은 바로 다운로드하지 않고 콘텐츠를 확인한 뒤 선택 메뉴를 연다.
- 영상 / Reel: `영상 저장` / `음원 저장` / `이미지 저장` / `3개 모두 저장`
- 사진: `원본 사진 저장`
- 슬라이드: `전체 개별 저장`
- 선택 메뉴와 저장 진행/결과 표시를 분리한다.
- 공통 Activity에서 확인 / 저장 / 실패 상태를 표시한다.
- 기존 진단/저장 설정 패널은 P0.5B 전까지 임시 관리 UI로 유지한다.

## 현재 작업 순서

### P0 — v0.8.9 업데이트 복구 확인
- 북마크 주소를 변경하지 않는다.
- 현재 남아 있는 Loader `RI 업데이트` 버튼으로 v0.8.9를 받아 실행한다.
- `RI 본체 실행 실패: Failed to fetch`가 다시 발생하지 않아야 한다.
- v0.8.9 실행 성공 후 떠 있는 Loader 업데이트 버튼이 사라져야 한다.
- 이후 업데이트는 본체 `저장 위치 · 기타 → RI 업데이트`에서 실행한다.

### P0.5A — UI / 선택 저장 실기기 확인
- Instagram 원래 3열 Grid가 그대로인지
- 스크롤 중 Grid overlay가 카드 위치를 따라가는지
- `저장`을 누르면 다운로드가 아니라 선택 메뉴가 먼저 나오는지
- 선택한 항목만 저장되는지
- 선택 카드와 저장 shortcode가 일치하는지
- Activity가 작업 상태만 표시하고 선택 메뉴와 섞이지 않는지

### P0.5B — 리서치 진입 / 창 골격
P0.5A 실기기 확인 뒤 진행한다.
- 공통 `리서치` 진입
- 간단 보기 / 상세 보기
- 상세 메뉴: 요약 / 콘텐츠 / 댓글 / 분석 / 미디어
- 전역 리서치 기본 골격
- 현재 임시 진단/설정 패널의 역할을 리서치 창으로 이동

### P0.6 — 수치 저장 / 계산
- 조회수 / 좋아요 / 댓글 / 재게시 / 게시일
- 참여율
- 24시간 snapshot
- 같은 계정 최근 게시물 중앙값 대비 계정대비
- 북마클릿 전용 history 사용
- missing 값을 0으로 생성하지 않음

### P0.7 — 실제 수치 연결
- Grid: 조회수 | 좋아요 | 댓글 | 재게시
- Grid: 참여율 | 24시간 | 계정대비 | 게시일
- Reel: 조회수 / 참여율 / 24시간 / 계정대비 / 게시일
- Feed: 참여율 / 24시간 / 계정대비 / 게시일
- 같은 값 재렌더링을 피해서 flicker 방지

### P1 — 콘텐츠 인식 / API 실패 보강
- Instagram API 404 실패 경로 확인
- 잘못된 인접 카드 fallback 금지
- 저장과 수치가 같은 shortcode를 사용하도록 고정

### P2 — 지정 폴더 지속성
- Edge 재실행 후 폴더 핸들 복원
- 권한 만료 시 저장 시점에만 재요청

### P3 — 미디어 최종 검증
- 실제 표지 우선
- 표지 없으면 정확한 0.000초 첫 프레임
- 영상 저장 수 초 수준 확인

### P4 이후
- P4: 본문 / 해시태그 / 언급 계정
- P5: 댓글 / 답글 / 실제 수집 범위
- P6: 음성 변환 / 화면 글자
- P7: 콘텐츠 / 댓글 분석
- P8: 저장 기록 / 수치 기록 / JSON / CSV 등 전역 데이터 관리

## 실기기 완료 기준
- Instagram 원래 3열 Grid가 변하지 않는다.
- 저장 버튼이나 수치 때문에 카드 크기·행 높이가 바뀌지 않는다.
- 선택한 콘텐츠와 저장 파일/수치의 shortcode가 일치한다.
- 확인되지 않은 수치는 `0`이 아니라 missing 상태다.
- 영상은 소리 포함 정상 재생된다.
- 지정 폴더 모드의 모든 저장 진입점이 같은 폴더를 사용한다.
